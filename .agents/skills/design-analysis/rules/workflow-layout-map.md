# 第一步：建立布局 Map

## 概述

在抠细节之前，先拿到页面的**全局骨架**：页面状态、整体尺寸、区域划分、区域间关系。

## 必须记录的内容

| 项目 | 说明 |
|------|------|
| 页面/界面状态 | 多 frame 时**分别标注 id 与用途**（默认态、hover、空态、弹窗态、移动端） |
| 整体尺寸 | 宽、高（px） |
| 区域列表 | 按**从上到下（y）**排序：区域名、`x/y/w/h`、主要子元素（含文字、图片） |
| 区域间间距 | 上区底部 → 下区顶部的垂直间距 |
| 每区四类重点 | 文字 / 图片 / 布局 / 层级，**不可遗漏、错位、丢层**（细节在第二步） |

## 操作步骤

### 1. 获取整体信息

用 Pencil MCP 拉取设计稿结构与截图：

- `get_screenshot` → 先看整体视觉
- `snapshot_layout` → 拿层级与布局数值
- `batch_get` → 取指定节点的详细属性

Figma 稿用 Figma MCP 取截图与节点上下文；或先粘贴进 Pencil 再读。

### 2. 识别区域边界

按 `analysis-order.md` 的「从上到下」切分横向「带」：

```
典型管理后台布局（参考本项目 MainLayout）:
┌────────────┬──────────────────────────┐
│  侧边栏     │  顶栏 (header)           │  ← 区域 2
│  (aside)   ├──────────────────────────┤
│            │  内容区 (main)           │  ← 区域 3
└────────────┴──────────────────────────┘
     ↑ 区域 1
```

- 区域边界以**容器**为准，不要按视觉元素猜
- 若页面有弹窗/抽屉/下拉，**单独列为一个状态**，不与主布局混记

### 3. 记录区域间关系

- 父子关系（内容区是 header 的兄弟还是父容器的子元素）
- 是否 sticky / fixed / 可滚动
- 比例关系（侧边栏固定 220px、内容区自适应）

## 输出格式

```markdown
## 布局 Map

- **状态**：默认态（另有「弹窗态」见第 N 节）
- **整体尺寸**：1440 × 900

| # | 区域 | x | y | w | h | 主要子元素 |
|---|------|---|---|---|---|-----------|
| 1 | 侧边栏 aside | 0 | 0 | 220 | 900 | Logo、菜单项 ×N |
| 2 | 顶栏 header | 220 | 0 | 1220 | 60 | 标题、用户下拉 |
| 3 | 内容区 main | 220 | 60 | 1220 | 840 | 统计卡片 ×4、表格 |

**区域间距**：header 底部(60) → main 顶部(60)，间距 0（紧贴）
```

## 自检

- [ ] 所有 frame / 状态都已识别并标注用途
- [ ] 整体宽高已记录
- [ ] 区域按 y 升序排列，`x/y/w/h` 齐全
- [ ] 区域间垂直间距已记录（不要留空）
- [ ] 每区的主要子元素已列出
- [ ] 层级关系（父子/兄弟）明确

## 常见错误

| 错误 | 后果 |
|------|------|
| 跳过本步直接抠按钮样式 | 后面发现整体布局理解错了，全部返工 |
| 把弹窗记进主布局 | 实现时结构错位，弹窗变成页面内元素 |
| 区域间距留空 | 实现时靠猜，垂直节奏全错 |
| 只记一个状态 | 漏掉空态/加载态，页面只有数据时才正常 |
