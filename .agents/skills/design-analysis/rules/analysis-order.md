# 分析顺序（必守）

## 重要性

必须按以下顺序阅读与记录设计稿，否则容易产生疏漏。
**不按顺序是遗漏与还原错误的主要来源之一**——跳着看、凭印象合并，必然漏项。

## 1. 从上到下

先按垂直方向，从页面最上方扫到最下方，确定所有横向「带」与区块的先后顺序。

- 与前端布局一致（块级元素默认自上而下堆叠）
- **避免漏掉顶部/首屏大字号文案**（banner 标题、副标题、CTA 最容易被跳过）
- 顺带记录每条「带」之间的垂直间距（上区底部 → 下区顶部）

**产出**：区域按 y 坐标排序的有序列表。

## 2. 从左到右

同一行或同一层级内，按从左到右依次记录。

- **不跳过、不凭印象合并**（三个并排卡片不能记成"一排卡片"了事）
- 避免只记左侧漏右侧（右侧常是次要操作、图标、关闭按钮）
- 同层元素的宽度分配要记清（等分 / 固定 / 自适应）

**产出**：每个横向区域内元素的有序列表 + 各自宽度。

## 3. 从外到里

每个区块内按「外层容器 → 内层容器 → 叶子元素」逐层进入，先轮廓后细节。

- 保证层级嵌套正确，**不丢层、不顺序颠倒**
- 先记容器（尺寸、内边距、排列方式），再记子元素
- 叶子元素（文字、图标、按钮）是最后一层

**产出**：每个区域的嵌套树。

## 执行方式

```
对页面:
  for 区域 in 按 y 升序:
    记录区域框(x,y,w,h) + 区域间垂直间距
    for 元素 in 按 x 升序:
      记录元素框 + 类型
      if 是容器: 递归进入（从外到里）
      else: 记录四类重点（文字/图片/布局/层级）
```

## 自检

- [ ] 区域列表的 y 坐标单调递增
- [ ] 同一区域内元素的 x 坐标单调递增
- [ ] 每个容器都记录了，没有直接跳到叶子元素
- [ ] 首屏顶部的文案没有漏
- [ ] 右侧/末尾的次要元素没有漏

## 反例

| 错误做法 | 后果 |
|----------|------|
| 从最显眼的按钮开始看 | 漏掉页面整体布局与顶部文案 |
| 看到"一排卡片"就记一行 | 丢失卡片数量、宽度、间距 |
| 直接记录按钮文字 | 丢失按钮所在容器与层级，实现时找不到归属 |
| 凭记忆补全 | 尺寸、间距全错 |
