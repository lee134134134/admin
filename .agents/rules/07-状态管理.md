# 状态管理（NON-NEGOTIABLE）

## 技术选型

- **必须使用 Pinia 3**，风格为 **setup store**（`defineStore('id', () => {...})`）
- **禁止**引入 Redux / Zustand / MobX 等其他方案，禁止 `options store` 写法（除非改造存量并全局统一）
- `main.ts` 已 `app.use(createPinia())`，组件内直接使用，不要重复注册

## Store 文件组织

| 约束 | 说明 |
|------|------|
| 位置 | 一律 `src/stores/<模块>.ts` |
| 数量 | **单文件单模块**，禁止把多个业务塞进一个 store |
| 导出 | `export const useXxxStore = defineStore('xxx', () => {...})` |
| 命名 | hook `use` + PascalCase；store id 用短横线或小写单词，全局唯一 |
| 禁止 | 新建 `src/state/`、`src/store/`（单数）、在组件内定义跨页状态 |

## 标准写法

```ts
import { ref } from 'vue'
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', () => {
  const token = ref<string>(localStorage.getItem('token') ?? '')
  const name = ref<string>('')

  function setToken(value: string) {
    token.value = value
    localStorage.setItem('token', value)
  }

  function logout() {
    token.value = ''
    name.value = ''
    localStorage.removeItem('token')
  }

  return { token, name, setToken, logout }
})
```

## 状态归属边界（NON-NEGOTIABLE）

| 状态类型 | 放哪 | 示例 |
|----------|------|------|
| 跨页面共享、刷新需保留 | Pinia store | 登录 token、当前用户 |
| 跨页面共享、可派生 | Pinia store + `computed` | 未读数 |
| 组件内部、仅本组件用 | `ref` / `reactive` | 表单草稿、弹窗开关 |
| 路由带来的 | `useRoute()` | 当前路径、`meta.title` |
| URL 即状态 | 路由 query/params | 列表筛选、分页 |

> **优先级：能用 props/emit 解决的不用 store，能用 URL 表达的不进 store。**
> 只有**确实被两个及以上不相关组件**需要时才上升为 store（YAGNI）。

## 编写约束

- 状态声明 `ref<T>` **带显式类型**，禁止 `ref()` 裸用导致推断为 `Ref<undefined>`
- store 只存**数据与业务行为**，不耦合 UI（不 import 组件、不操作 DOM、不弹 ElMessage 除非是纯业务提示）
- 副作用（localStorage、请求）写在 store 的 action 里，**不要**散在组件中
- 需要派生值用 `computed`，不要存一份冗余副本再手工同步
- 禁止在 store 外部直接改内部 `ref`（通过 action 修改）

## 持久化

- 本项目**暂未使用** `pinia-plugin-persistedstate`
- 当前持久化方式：在 action 内显式读写 `localStorage`（见 `stores/user.ts`）
- token 的读写**集中在 `useUserStore`**；`router/index.ts` 的守卫允许直接读 `localStorage.getItem('token')`（避免循环依赖），**其余位置禁止**直接操作 token 的 localStorage
- 需要引入持久化插件时，先更新本文件与 `01-项目概述`
