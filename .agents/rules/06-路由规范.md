# 路由规范（NON-NEGOTIABLE）

## 路由注册位置

- **全局唯一路由表**在 `src/router/index.ts`，集中声明
- **禁止**散落创建 `src/router/modules/*.ts`、禁止在组件内 `addRoute`
- 同一页面组件**只允许被一处** `import()` 引入

## meta 契约

```ts
{
  path: 'calendar',
  name: 'calendar',
  component: () => import('@/views/CalendarView.vue'),
  meta: { title: '日程日历' },        // 需登录
}
```

| 字段 | 必填 | 语义 |
|------|------|------|
| `meta.title` | **是** | 顶栏标题（`MainLayout` 读 `route.meta.title`），**缺失会导致顶栏空白** |
| `meta.public` | 标记即生效 | `true` = 免登录；**缺省即需登录** |
| `name` | 推荐 | 唯一、camelCase，用于 `router.push({ name })` |

> **新增页面必须设置 `meta.title`。** 未标 `meta.public` 的路由会被全局守卫拦截。

## 守卫行为（不要破坏）

```ts
router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  if (!to.meta.public && !token) return { name: 'login', query: { redirect: to.fullPath } }
  if (to.name === 'login' && token) return { path: '/' }
})
```

- 无 token 访问受保护路由 → 跳 `/login?redirect=<原路径>`
- 已登录访问 `/login` → 回 `/`
- **禁止**绕过守卫直接在页面内自行判断登录态来做权限

## 层级结构

- 独立全屏页（登录、404）放**顶层**路由
- 需要侧边栏 + 顶栏的页面放 `MainLayout` 的 `children` 下
- `/` 设 `redirect: '/dashboard'`
- 通配 `/:pathMatch(.*)*` → `redirect: '/'`（保留兜底）

## 懒加载（NON-NEGOTIABLE）

- 页面组件一律 `component: () => import('@/views/XxxView.vue')`
- **禁止**顶层静态 `import` 页面组件（会拖慢首屏）
- 唯一例外：`MainLayout` 是布局容器，静态引入

## 路由 ↔ 菜单一致性（NON-NEGOTIABLE）

新增需要出现在侧边栏的页面时，**必须同时改两处**，否则菜单与路由不一致：

1. `src/router/index.ts` 注册路由
2. `src/layouts/MainLayout.vue` 的 `el-menu` 增加 `<el-menu-item index="/xxx">`

- `index` 值必须与 `path` **完全一致**（`el-menu` 靠 `index` 高亮与跳转）
- 图标用 `@element-plus/icons-vue` 中已全量注册的图标组件
- 仅个人工具类页面（如登录）不进菜单

## 新页面检查清单

- [ ] `meta.title` 已设置
- [ ] 是否需要 `meta.public` 已判断
- [ ] 用了懒加载 `() => import(...)`
- [ ] 需要菜单则已同步 `MainLayout.vue`，`index` 与 `path` 一致
- [ ] `pnpm type-check` 通过
