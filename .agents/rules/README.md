# 项目规范索引（Rules）

本目录是本项目的**开发规范唯一维护源**，按「开发时会被问到的决策类型」拆分为 11 个文件。
规范只写**原则与约束**（是什么 / 不能是什么）；**怎么做**的步骤与示例在 `.agents/skills/`。

> 这些文件**不会自动加载**——需要确认某类规范时**主动读取**对应文件。

## 规范模块

| # | 规范 | 何时读取 |
|---|------|----------|
| 01 | [项目概述](./01-项目概述.md) | 需要了解项目背景、技术栈、后端接口约定时 |
| 02 | [编码规范](./02-编码规范.md) | 编写或审查任何代码时（命名、TS 约束、导入、注释语言） |
| 03 | [项目结构](./03-项目结构.md) | 不确定代码该放哪个目录时 |
| 04 | [组件规范](./04-组件规范.md) | 创建、修改或拆分组件时 |
| 05 | [API 规范](./05-API规范.md) | 新增、修改或调用后端接口时 |
| 06 | [路由规范](./06-路由规范.md) | 新增页面或调整路由/菜单时 |
| 07 | [状态管理](./07-状态管理.md) | 新增或重构全局状态时 |
| 08 | [通用约束](./08-通用约束.md) | 确认全局硬性限制时（语言、占位、依赖、目录边界） |
| 09 | [样式规范](./09-样式规范.md) | 编写组件样式或使用主题变量时 |
| 10 | [文档规范](./10-文档规范.md) | 编写注释、README 或交付文档时 |
| 11 | [测试规范](./11-测试规范.md) | 改动完成需要验收、确认「什么算通过」时 |

## 快速查找

| 需求 | 规范文件 |
|------|----------|
| 项目是什么？用什么技术栈？后端怎么接？ | 01-项目概述 |
| 怎么命名变量/函数/类型？能用 `any` 吗？ | 02-编码规范 |
| 这段代码该放哪个目录？ | 03-项目结构 |
| 怎么写一个组件？Props 怎么定义？什么时候抽通用组件？ | 04-组件规范 |
| 怎么加一个接口？函数叫什么名？错误谁处理？ | 05-API规范 |
| 怎么加一个页面？菜单怎么同步？`meta` 怎么写？ | 06-路由规范 |
| 这个状态该放 store 还是组件里？ | 07-状态管理 |
| 注释用什么语言？能硬编码图片/色值吗？ | 08-通用约束 |
| 样式怎么命名？Element Plus 主题怎么改？ | 09-样式规范 |
| 什么情况必须写注释？ | 10-文档规范 |
| 改完怎么算通过？要跑哪些命令？ | 11-测试规范 |

## 标记说明

- **`（NON-NEGOTIABLE）`** — 硬约束，不可协商，违反即为缺陷
- 未标记的为约定与推荐，破坏前应说明理由

## 与 Skills 的分工

| | Rules（本目录） | Skills（`../skills/`） |
|---|---|---|
| 回答 | 怎么才算对 | 一步步怎么做 |
| 形态 | 原则、约束、契约、命名表 | 步骤、检查点、模板、示例代码 |
| 加载 | 按场景读取 | 执行该任务时读取 |
| 典型 | 「接口必须放 `src/api/`」 | 「新增接口的 5 个步骤」 |

## 维护约定

1. 新增规范：建 `NN-名称.md` + 更新本索引的两张表
2. 拆分/合并规范：同步更新索引与 `.agents/README.md`
3. **规范变更必须与代码同步**——过期的规范比没有规范更糟
4. 内容需与真实代码一致；发现不一致时**以代码为准**，修规范或提整改
