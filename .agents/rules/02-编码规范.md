# 编码规范

## TypeScript 规范（NON-NEGOTIABLE）

- 严格模式下工作，**禁止**用 `@ts-ignore` / `@ts-expect-error` 压制类型错误
- **禁止 `any`**；需要宽松类型时用 `unknown` 并做收窄，或定义明确的接口
- **API 返回类型必须显式声明**：`httpGet<DashboardStats>(...)`，不允许靠推断
- 接口/类型别名用 `PascalCase`
- `tsconfig.app.json` 已开 `verbatimModuleSyntax`：类型导入需用 `import type { X } from '...'`
- 已开 `noUnusedLocals` / `noUnusedParameters`：不要留下未使用的变量、导入、参数

## 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| 文件（.ts / 目录） | camelCase 或 kebab-case，与现有保持一致 | `request.ts`、`MainLayout.vue` |
| Vue 组件文件 | PascalCase | `CalendarView.vue`、`MainLayout.vue` |
| 变量 / 函数 | camelCase | `activeMenu`、`handleLogout` |
| 常量 | UPPER_SNAKE_CASE（模块级不变量） | `API_TIMEOUT` |
| 接口 / 类型 | PascalCase | `CalendarEvent`、`LoginResponse` |
| Pinia store | `use` + PascalCase + `Store` 语义 | `useUserStore` |
| CSS 类名 | BEM：`block__element--modifier` | `main-layout__aside` |
| 事件处理函数 | `onXxx` 或 `handleXxx` | `handleLogout`（现有惯例） |
| 本地函数 | 动词开头 | `setToken`、`createCalendarEvent` |

> **组件内事件处理器统一用 `handleXxx`**（与 `MainLayout.vue` 现状一致）。

## 注释语言（NON-NEGOTIABLE）

- **注释、UI 文案、提交信息用中文**
- **变量、函数、类型命名用英文**
- 注释风格沿用现状：行注释 `//` 说明「为什么」，JSDoc `/** */` 说明导出 API
- 中文注释用半角冒号 + 空格：`// 全局前置守卫: 未登录跳转登录页`

## 导入顺序

沿用现有惯例，保持块状分组：

1. Vue / 第三方库
2. 项目内部模块（`@/` 别名优先）
3. 类型导入（`import type`）
4. 副作用导入（样式、`'element-plus/dist/index.css'`）放最后

```ts
import { computed } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { useUserStore } from '@/stores/user'
```

## 别名（NON-NEGOTIABLE）

- 项目内部导入**一律用 `@/`** 指向 `src/`
- **禁止**深层相对路径（`../../../utils/xxx`）
- 唯一例外：`src/api/` 内部模块之间可用 `./request`（同目录，现有惯例）

## 其他

- 优先用 Composition API + 组合式函数，**不滥用全局 store**
- 不写无意义的抽象；单个文件接近 400 行时考虑拆分（见 `04-组件规范`）
